# Garmin CN / Global 双向活动合并同步

## 1. 背景
团队希望复用 [running_page](https://github.com/yihong0618/running_page) 的 Garmin 同步能力，实现以下目标：

1. 同时接入 Garmin 中国（CN）与 Garmin 国际（Global）两个账号。
2. 将两个账号中的活动进行合并去重（merge）。
3. 将缺失活动双向补齐，最终两端数据一致。
4. 以 daemon 常驻方式定时执行。
5. 不引入第三方基础组件（数据库、消息队列、缓存等）；持久化仅使用本地文件。

## 2. 术语
- **CN 账号**：Garmin 中国区账号。
- **Global 账号**：Garmin 国际区账号。
- **活动（Activity）**：一次运动记录（跑步/骑行等）。
- **指纹（Fingerprint）**：由活动关键字段计算得到的稳定标识，用于跨账号去重。
- **同步轮次（Sync Run）**：一次完整的双向同步执行。

## 3. 范围

### 3.1 In Scope
- 复用 `running_page/run_page/garmin_sync.py` 中已存在能力（拉取、下载、上传）。
- 双向增量同步（CN -> Global、Global -> CN）。
- 基于文件的状态持久化、失败重试、幂等保障。
- daemon 定时运行与日志输出。

### 3.2 Out of Scope
- Web 管理后台。
- 第三方数据库或云服务依赖。
- 跨品牌设备平台（如 Strava、Nike Run Club）同步。

## 4. 业务需求

### BR-1 双向同步
系统必须在每个同步轮次内完成双向对齐：
- CN 中存在但 Global 缺失的活动，需要补传到 Global。
- Global 中存在但 CN 缺失的活动，需要补传到 CN。

### BR-2 合并去重
系统必须对同一实际活动进行去重，避免重复上传。

### BR-3 最终一致性
在网络和接口稳定的前提下，多次轮询后，两个账号活动集合应趋于一致。

### BR-4 可持续运行
系统必须支持 7x24 daemon 常驻运行，定时触发同步。

### BR-5 可恢复
系统在崩溃重启后，必须可从文件状态继续运行，不重复制造脏数据。

## 5. 功能需求

### FR-1 账号连接
- 支持加载 CN/Global 两套凭证。
- 支持凭证失效检测与明确报错。

### FR-2 增量拉取
- 支持基于时间窗口（`lookback_days`）拉取活动。
- 支持首次全量索引构建与后续增量刷新。
- CN 与 Global 两侧活动拉取应支持并行执行，避免串行等待导致的轮次延迟。

### FR-3 标准化与指纹
- 将两侧活动转换为统一结构。
- 生成稳定指纹用于跨账号匹配。

### FR-4 差集计算
- 计算 `cn_only` 与 `global_only` 两组待同步活动。

### FR-5 双向上传
- 按差集结果执行双向上传。
- 单条上传结果必须写入状态文件。

### FR-6 重试机制
- 上传失败活动进入失败队列。
- 失败项支持指数退避重试。

### FR-7 幂等控制
- 对已同步活动必须保证重复运行不会重复上传。

### FR-8 日志与审计
- 每轮同步输出汇总日志（拉取量、差集量、成功量、失败量、耗时）。
- 保留活动级审计信息（来源、目标、时间、结果）。

### FR-9 并发执行控制
- 系统应支持并行子任务执行（双侧拉取、双向上传、失败重试）。
- 系统应提供并发度配置（如 `fetch_workers`、`upload_workers`）。
- 系统应保证并发下幂等一致性，不因重复任务调度导致重复上传。

## 6. 非功能需求

### NFR-1 可靠性
- 同步轮次异常不应导致 daemon 退出。
- 支持下一轮自动恢复。

### NFR-2 性能
- 单轮执行时间应小于调度周期。
- 文件索引需支持定期 compact，避免无限膨胀。
- 在活动规模增长时，应通过受控并发保持轮次耗时线性可控。

### NFR-3 可维护性
- 关键状态文件需采用可读格式（JSON/JSONL）。
- 配置项集中管理并支持注释文档。

### NFR-4 安全
- 凭证通过环境变量注入，不落盘明文。
- 日志中不得打印敏感字段。

## 7. 约束
1. 不使用 SQLite、Redis、Kafka 等第三方组件。
2. 持久化仅允许本地文件。
3. 复用 `running_page` 现有 Garmin 交互逻辑，减少重复实现。

## 8. 输入输出

### 输入
- 两个 Garmin 账号凭证（CN、Global）。
- 同步配置（间隔、回看天数、重试策略、同步开关）。

### 输出
- 两侧账号活动数据双向补齐。
- 状态文件、映射文件、失败队列、运行日志。

## 9. 验收标准
1. 已同步数据重复执行 3 轮后无新增重复上传。
2. 人工构造 CN 单边新增活动后，最多 2 个调度周期内出现在 Global。
3. 人工构造 Global 单边新增活动后，最多 2 个调度周期内出现在 CN。
4. 模拟进程异常退出后重启，可继续同步且无批量重复。

- 测试数据来源采用“手工构造 + 脱敏 fixtures”，不依赖线上真实 Garmin 数据。

## 10. 风险与假设

### 假设
- Garmin CN/Global 接口可稳定访问。
- 活动导出文件（FIT/GPX）可用于跨账号上传。

### 风险
- 双端平台对同一活动元数据可能存在字段偏差，导致误判。
- 高频同步可能触发平台风控或限流。
- 仅文件持久化在超大规模数据下检索性能下降。

## 11. 评审重点（需拍板）
- 需要重点评审并拍板的条目见：`docs/garmin-bisync-review-checklist.md`。
- 至少应对以下参数形成明确结论：去重容差、并发度、同步范围、失败策略、告警阈值。
