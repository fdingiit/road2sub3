# Garmin CN/Global 双向同步评审重点（请重点拍板）

> 目标：帮助产品/技术负责人快速判断方案是否可上线，明确必须拍板的决策项。

## A. 必须拍板（Blocking）

1. **数据一致性定义**
   - 你们接受“最终一致”（多轮收敛）还是要求“单轮强一致”？
   - 建议：采用最终一致，否则会显著增加失败回滚复杂度。

2. **去重规则阈值**
   - 时间/距离/时长容差是否采用默认值（±120s / ±2% / ±5%）？
   - 若业务对误合并敏感，建议先收紧阈值并观察误判率。

3. **并发与限流策略**
   - `upload_workers` 上限是多少（建议 4~8）？
   - 是否需要夜间低峰提升并发、白天降并发？

4. **失败处理策略**
   - 重试上限后是“终态失败告警”还是“持续低频重试”？
   - 建议：达到上限后转终态 + 告警，避免无限重试。

5. **隐私与同步范围**
   - 私密活动是否同步？
   - 是否同步历史全量（一次性）还是只同步最近 N 天？

6. **运维告警门槛**
   - 连续失败几轮触发告警（建议 >=3）？
   - 单轮失败率阈值多少触发告警（建议 >20%）？

## B. 强烈建议评审（High Impact）

1. **文件持久化可接受规模**
   - 预计活动量级（每月新增、总量）？
   - 是否接受定期 compact 带来的短暂 I/O 峰值？

2. **崩溃恢复语义**
   - “上传成功但未写 state”时，以 mapping 为准是否可接受？
   - 是否需要额外人工对账脚本？

3. **测试准入门槛**
   - 是否将 FR-1~FR-9 覆盖矩阵作为发布前硬门槛？
   - 是否要求并发/恢复场景必须在 CI 通过？

## C. 可后置优化（Non-blocking）

1. Web 可视化面板（当前 out of scope）。
2. 更细粒度活动字段对账报告。
3. 自动调参（按错误率动态调整并发）。
